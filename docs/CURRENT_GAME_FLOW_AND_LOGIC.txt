SOURCE AND STATUS CONVENTION
This document describes the inspected scenes, scripts, resources and organized asset files.
It is not a copy of the design brief. No Godot launch, parser check, automated test or
post-implementation playtest was run for this integration, as requested by the developer.
Image dimensions, alpha channels, source manifests and file metadata were inspected to
choose asset regions before editing. Existing gameplay was read, not newly certified.

[WORKING] = an existing implemented, connected code path; not a new runtime test claim.
[PARTIAL] = implementation/presentation exists but has a stated limitation or awaits manual confirmation.
[PLACEHOLDER] = deliberate temporary art, text or empty audio hook.
[BROKEN] = a concrete source-evident defect, described explicitly.
[NOT IMPLEMENTED] = no corresponding current feature.
New sprite/audio wiring is [PARTIAL] until the developer imports and plays it in Godot.

1. EXACT F5 GAME FLOW
==================================================
[WORKING] Code entry path:
F5 -> project.godot run/main_scene = res://scenes/ui/front_end.tscn -> HOME.
Autoloads initialize in this order: EventBus, FreedomLedger, GameManager, NoiseModel,
SessionSettings. GameManager starts with zone="intro", entry="start", state=MENU.
HOME offers Start Game, Story, Controls, Settings, Credits and desktop Quit.
Start Game locks input, fades to black over 0.32 seconds, calls GameManager.new_game,
clears the ledger/checkpoint/ending, sets state=INTRO, and opens scenes/ui/loading_screen.tscn.
Loading shows a bottom LOADING... button and advances automatically after 5.0 seconds
(including its final 0.32s black fade). Main loads normally behind opaque black; threaded
requests/polling were removed after a reported stuck screen. Load errors offer Return Home.
Main's existing Player, UI, Audio and Awakening children initialize.
Main._ready loads res://scenes/levels/intro_floor.tscn under World.
EstateRoom reads res://data/estate_layout.json and builds geometry, props and markers.
Main places Player at PlayerSpawn (240,490), applies camera bounds, and starts Awakening.
No enemy is created in the intro.

After about 11.7 seconds of unpaused intro time, control becomes available.
Walk to the flashlight (430,480) and tool kit (900,430); press E near each.
Try intro_exit (1590,362): the first interaction only acknowledges the lock.
With both pickups, another E performs the short lock beat and corridor focus, opens
the door over a dark threshold, and walks Els through it.
GameManager.travel("ground") reloads Main with the ground-floor instance.
Els emerges from the initially open arrival door, walks to y=418, closes it, then
Main saves an entry checkpoint and creates The Deprived One in Entities.

Main progression:
Ground: piano_seal at (1800,435), three E completions of 0.9 seconds each.
Then hearing_key at (1960,525): restores Hearing, saves checkpoint.
upper_stairs at (6980,362) requires hearing -> upper, entry=start.
Upper: vanity_seal (2150,440), requires hearing, three 1.1-second completions.
Then sight_key (2370,480): restores Sight, saves checkpoint.
basement_stairs (6980,362) requires sight -> basement, entry=start.
Basement: ritual_seal (4090,430), requires sight, three 1.25-second completions.
Then memory_key (4310,480): restores Memory, saves checkpoint.
service_return (6890,362) requires memory -> ground, entry=end.
Return left to front_door (180,362), press E with three keys -> Full Awakening.

All other actual transitions:
- Upper ground_stairs (180,362) -> ground, entry=end, no additional gate.
- Basement upper_stairs (180,362) -> upper, entry=end, no additional gate.
- Basement maintenance_exit (620,362) with exactly two keys -> Partial Mercy.
- Ground custodian_seal (5900,430) with <=1 key and >=3 letters -> Vantree.
- Caught -> 1.2-second sequence -> saved room/position/ledger -> Main reload.
- Restart checkpoint -> saved snapshot, or New game when no checkpoint exists.
- New game -> clear progression and checkpoint -> Loading -> intro Main.
- Pause and letter reading suspend the scene tree; Resume/Close return to prior state.
- Ending -> ending overlay; New game or Quit. No scene beyond an ending exists.

All four active room groups and three ending triggers are connected in code.
There is no return transition into the foyer after leaving it.
No progression blocker was established by the source inspection after path repair,
but this is not proof of a completed live run with the new assets.

MANUAL F5 PROCEDURE (for the developer, not executed by the agent):
1. Open project.godot in 4.7.2 and let the moved textures/WAVs import.
2. F5; choose START GAME on HOME; wait for Els to rise. Move in all eight input directions.
3. Compare walk, Shift sprint and Ctrl crouch; release movement and confirm footsteps stop.
4. Collect both foyer items and try/open the door as described above.
5. Complete the ground piano and Hearing Key. Compare sprint noise with crouch/carpet.
6. Continue to Sight; compare flashlight/exposed movement with darkness and crouch.
7. Enter/leave blue hiding props using E. Continue through the basement ritual for Memory.
8. Use the service return/front door for Full Awakening. Use separate runs/checkpoints
   for Partial Mercy before Memory and Vantree before taking more than one key.
9. Confirm death, checkpoint restart, letters, Esc/settings and New game.
These are manual instructions, not completed test results.

6. PLAYER FOOTSTEPS
==================================================
[PARTIAL] Newly wired; no playback test run.
Folder: res://assets/audio/Footsteps/
Seven WAV files, all explicitly named Antons_Footsteps_FS_Wood_Walk_01..07.wav.
Only source category: WOOD. No UNCLASSIFIED files and no other material recordings.
Each is stereo 44,100 Hz, 24-bit PCM; durations approximately 0.216-0.465 seconds.
res://scripts/player/footstep_audio.gd is attached to Player/FootstepAudio.
The Player scene explicitly assigns all seven AudioStreams to wood_samples.

Movement's existing step timer calls both NoiseModel.emit_step and FootstepAudio.play_step.
Crouch cadence=0.52 s; walk=0.42 s; sprint=0.27 s. No second gameplay timer was added.
A step needs real velocity >10, control enabled, PLAYING state and no hiding.
Audio tails stop when these conditions cease; nodes inherit scene pause.
Two SFX voices alternate, allowing short tails to overlap during a faster gait.
Volume defaults: crouch=-20 dB, walk=-10 dB, sprint=-4 dB, before bus mixing.
Pitch varies uniformly from 0.975 to 1.025 by default.
A random sample is selected excluding last_sample where alternatives exist.
Repeat avoidance compares streams across surface fallbacks, not just local indices.
No samples available -> silence, without changing gameplay noise.

surface_samples is an optional Inspector Dictionary: surface name -> Array of AudioStream.
Valid nonempty overrides are used first; unknown/empty/invalid banks fall back to wood_samples.
WOOD, STONE, CARPET, WATER, GLASS and GENERIC therefore currently SOUND like wood.
This is a presentation fallback, not a claim of six installed sound categories.
The existing surface_at() system is retained.

12. HEARING AI
==================================================
[WORKING] Enemy _hear:
Reject if no hearing_restored, already CHASE, or GameManager not PLAYING.
Accept only if distance to event <= intensity * hearing_scale (default 740).
While investigating for less than 1 s, ignore quieter follow-up noise.
Record intensity, target=event position, change to INVESTIGATE.
No acoustic wall occlusion; surface influences the event intensity, not an audio analyzer.
Examples on wood: crouch reach 44.4, walk 177.6, sprint 740 pixels.
Glass doubles those reaches; carpet multiplies by .35; water by 1.65; stone by .85.
Ordinary player contact <26 with clear collision-mask-1 sight can catch after Hearing,
even before vision restoration. Hidden players are exempt unless witnessed_hide matches.
Hearing restoration is the first permitted sense transaction.

==================================================
13. SIGHT AI
==================================================
[WORKING] Only enabled by sight_restored; hidden player is never directly visible.
Default range=390, full field_of_view=115 degrees.
Range multiplies by .6 while player crouches, .55 in non-exposed room locations,
and 1.75 while the flashlight is enabled. These modifiers multiply together.
Beyond 50 pixels, facing dot normalized offset must meet cos(FOV/2).
A ray from enemy+(0,-7) to player+(0,-7), mask=1, must be unobstructed.
Walls/furniture block the ray. Player/enemy bodies are on other layers.
On detection: last_seen=player position, lost_sight=0, observation_grace=.25,
player_detected signal and CHASE; route samples are stored only with Memory.
Ground is considered exposed. Upper exposure uses the three moonlight rectangles
(x=2650/4300/5950, width=650, player y<545); other upper positions are dark.
Basement is exposed for x>3900. Exposure is gameplay geometry, not sampled pixel light.
[PARTIAL] The placeholder beam is translucent geometry and is not clipped by walls;
detection itself still uses the blocking ray.

==================================================
14. MEMORY AI
==================================================
[WORKING] Only meaningful after memory_restored.
While visibly detecting player: save one route sample per second, maximum four.
On hiding signal: entrance is "observed" only with Sight, grace>0 and clear ray.
Only then set witnessed_hide; with Memory also retain the spot ID, unique/recent,
maximum three entries. Remote/unseen hiding signals are not globally recorded.
SEARCH after 1.5 s prefers the oldest retained spot, removing that entry on selection.
Otherwise extrapolate the last two observed positions by 240 pixels, clamp to room,
and enter PREDICT_HUNT. No actual exit graph or strategic route planner is used.
Arrival re-checks whether the player is hidden within 45 pixels; if so, caught.
Route history clears after reaching a prediction. Hidden history is consumed gradually.
All memory belongs to the enemy instance and clears on travel/checkpoint scene reload.
[PARTIAL] Nearby re-check uses distance without an additional ray; see section 28.
